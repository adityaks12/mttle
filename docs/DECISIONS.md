# Settled decisions

These are decided. Build against them. Do not relitigate in code. If one needs to change, raise it in chat first.

1. Name and domain: mttle, domain mttle.in. Wordmark "mttle", lowercase, no punctuation, no logo mark. (Renamed from Spot on 2026-09-30, that name wasn't available as a domain or wordmark.)
2. Identity: Kelly green. Tokens in the `site/index.html` :root block: signal #22C55E, signal-deep #15803D, signal-tint #DAF5E3, paper #F4F2EC, ink #17150F, muted #6E685C, line #E4E0D5. Type: Bricolage Grotesque (display), Hanken Grotesk (text). Buttons use the deep green for contrast.
3. Monetization: the customer pays a fee to unlock a trainer's direct contact, then arranges sessions with the trainer herself. Not a recurring subscription. Trainers free, no commission, for now. Do not build trainer billing yet. Avoid the label "one-time fee" in copy and docs, describe the mechanic instead. Exact pricing and reasoning: see local `docs/STRATEGY.md`, gitignored, not in this repo.
4. Price test: settled, in progress. Details (price points, which societies, rotation plan): see local `docs/STRATEGY.md`, gitignored, not in this repo.
5. Supply target: settled, a specific trainer count for month one. Exact number: see local `docs/STRATEGY.md`, gitignored, not in this repo.
6. Categories: general women's fitness and PCOS-friendly only, for now. Prenatal, postnatal, rehab and post-injury are deferred. This is today's scope, not a permanent limit, see `docs/PROJECT.md`'s Expansion section.
7. Delivery default: society (clubhouse) gym. At home is optional.
8. Geography: open in the Koramangala and HSR Layout corridor, in two or three specific adjacent mega-communities. This is today's wedge, not a permanent restriction, see `docs/PROJECT.md`'s Expansion section.
9. Architecture: two Google Forms (trainer intake, customer request) feeding the operating workbook, a live Google Sheet and single source of truth (Trainer_Master, Trainer_Availability, Trainer_Documents, Trainer_Reviews, Society_Master, Customer_Master, Customer_Requests, Introductions, Payments, Followups, Lists, Trainer_Onboarding_Log, Acquisition_Experiments). The operating workbook is kept entirely offline, not in this repo in any form, not even as a snapshot. `Trainer_Master` is never published to the web, and nothing in its file ever is. The browse page instead reads a second, entirely separate Google Sheet, "mttle — Public Trainer Feed," with no formula link to the operating workbook, hand-maintained with only public-safe columns for Active trainers (see `docs/SPEC.md`). Acquisition_Experiments is where the price test (above) gets logged. IDs and certificates live in an access-restricted Google Drive folder, referenced from Trainer_Documents, never in the open sheet.
10. Privacy and safety: display name (first name) only in public, never expose trainer phone, full name or ID client-side, record consent at onboarding via Consent to List and Consent to Share Contact, keep the not-a-medical-provider disclaimer, and ask the client safety question before each intro. This rule governs the published CSV too, not just the page: only the separate public feed sheet is ever published, never the operating workbook. Extends to reviews: a reviewer's name shows first-name (or initial) only, same as trainers, and a review is only ever published once the client has given permission to display it.
11. Fulfillment: concierge. The intro button messages the founder's WhatsApp. The founder confirms payment, then shares the contact. No needs-understanding call with the customer, it adds operational overhead and founder liability for the match itself; the customer selects the trainer from the browse page.
12. No automation at this stage. Drive, Forms and Sheets are manual. Google API automation is a later phase, not now.
13. Hosting: the GitHub repo (`mttle`) stays private. Connected to Netlify with publish directory `site`, never the repo root, so `docs/` and `forms/` never reach the public site regardless of repo visibility. Deploy is a manual `netlify deploy --prod`, see `docs/DEPLOY.md`. mttle.in points at it later.
14. Writing: no em or en dashes, sentence case, plain active voice.
15. No login: favourites save to the browser's local storage only, per device, no accounts, no server. Skipped a real login system because it would pull in a proper database for per-user data, session handling and account support, disproportionate overhead for a solo founder still validating whether people will pay at all. Revisit only with real evidence that customers need favourites to follow them across devices.
